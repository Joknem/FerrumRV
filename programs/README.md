# FerrumRV guest 自检程序

15 个独立 `.hex` 文件，入口固定为 `0x80000000`，无需 entry 行。每次启动程序都应重新创建 CPU 和清零的 Memory，**RAM 至少 4096 字节（4 KiB）**。代码位于 `0x80000000` 起，数据区从 `0x80000800` 起，两者不重叠。

## 文件格式与加载

```text
0x80000000: 0x00100093    # addi x1, x0, 1
```

每行是 `地址: 机器码 # 汇编及说明`。地址决定这条机器码写到哪里，不能忽略地址后仍然按行号装载。所有地址和机器码都是十六进制 u32 文本，小端存储由 `Memory::write_word` 完成。

最小加载流程：逐行读取 → 去掉 `#` 后面的注释 → 跳过空行 → 用 `split_once(':')` 拆出地址与机器码 → 两边分别 `trim()`、去掉 `0x`、按十六进制解析 → `mem.write_word(address, instruction)`。缺少冒号或数字解析失败应返回错误。以 `#` 开头的标签和段落说明仅供阅读，不占内存，也不需要加载器解析。

运行时读取 `programs/<name>.hex`，例如 `cargo run -- 09_sum_loop`，从仓库根目录启动。新增程序无需添加 Rust `match` 分支或重新编译。当前无需自定义 `ProgramError`；加载器由学生实现，保留现有通用错误返回即可。本格式是教学用清单，不承诺兼容任意 objdump 文本，也不是 objcopy 的原始二进制输出。

## 自检和停止协议

正常程序用比较和分支验证结果。全部通过才设置 `a0/x10=0` 并 EBREAK；检查失败跳到 `fail`，设置 `a0=1` 并 EBREAK。monitor 在 halted 后读取 a0，分别显示 PASS 或 FAIL。EBREAK 在 CPU 内仍只负责设置 halted。

`13/14` 是故障演示：正确结果是分别报告 Decode / Execute 错误，不能报告 PASS。它们先完成正常计算和访存，再触发故障；触发前 a0 保持 99，正常准备阶段检查失败则以 a0=1 停机。monitor 无需按文件名特殊处理。

自检依赖基础算术、比较和分支，不能代替独立的 host 单元测试，也不声称穷尽 RV32I。批量执行应设置步数上限（本次验证使用 10000 步）。

## 程序目录

“指令数”包含 PASS/FAIL 出口及函数体，“执行步数”是正常路径实际执行次数；循环会重复执行指令，未取的失败路径不会执行。

| 文件 | 指令数 | 执行步数 | 学习/验证内容 |
|---|---:|---:|---|
| 00_add_sub.hex | 66 | 91 | 回绕、符号边界、寄存器重叠、1..10 累计和 |
| 01_logic.hex | 69 | 67 | 交错位掩码、全零全一、XOR 可逆性 |
| 02_immediate_logic.hex | 74 | 72 | 正负立即数、符号扩展、多组输入 |
| 03_register_shift.hex | 94 | 92 | 三种移位，移位量 0/1/4/31/32/33/63 |
| 04_immediate_shift.hex | 74 | 72 | 三种立即数移位，边界与字节提取 |
| 05_compare.hex | 83 | 75 | 四种比较、六种条件分支的取与不取 |
| 06_word_memory.hex | 80 | 120 | SW/LW 多组位模式、相邻哨兵、数组循环 |
| 07_byte_memory.hex | 90 | 130 | SB 截断、LB/LBU 扩展、邻字节保持、数组循环 |
| 08_halfword_memory.hex | 92 | 132 | SH 截断、LH/LHU 扩展、邻半字保持、数组循环 |
| 09_sum_loop.hex | 46 | 278 | 前缀和数组、反向遍历、嵌套循环、Fibonacci |
| 10_jump_links.hex | 38 | 92 | 循环调用、嵌套调用保存返回地址、JALR 清低位和 rd=rs1 |
| 11_upper_immediate.hex | 46 | 44 | LUI 覆盖旧低位、AUIPC 正负偏移、PC 相对访存 |

| 13_fail_decode.hex | 32 | 65（含故障尝试） | 正常循环后，在 `0x80000074` 解码非法 STORE |

`14_fail_memory` 的预期越界以 RAM 恰为 4096 字节为前提；若增大 RAM，需要调整故障地址。

## 验证记录

- 用 LLVM 汇编器独立核对 1029 条合法指令与行内汇编完全一致；另有 1 条故意非法的 STORE。
- 使用当前项目的 Cpu / Memory 和独立临时装载驱动：13 个正常程序全部 PASS，2 个故障程序在表中 PC 返回预期错误。
- 对每个正常程序，在验证用内存副本中强制第一处结果检查走失败分支，均能以 a0=1 停机；原始文件未做此改动。
- 上述执行验证未经过学生正在实现的 `load_program` 和 monitor；接入新格式仍属于本章任务。
